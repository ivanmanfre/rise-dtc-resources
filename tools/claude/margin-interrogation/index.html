The prompts

Four prompts, run in order, in one Claude chat

Each block prints the prompt on its own, then the exact thing you paste under it. Keep them in the same chat and in this order, because each answer is the input to the next one. Every prompt is on this page in full, and the copy button puts it on your clipboard.

01

Rebuild the base

Turns your two result blocks into one per-order arithmetic line, checked to the cent against your Contribution Margin figure, so every prompt after this one runs on a verified base.

You are running a margin interrogation on my store. Work only from the numbers I paste. Compute
nothing from memory and quote no outside figure at any point in this chat.

STANDING RULES for every line you write in this chat, from this message to the last one:
- Plain markdown only. Use headings, tables and fenced code blocks. Write no LaTeX and no math
  delimiters.
- Zero em dashes. When a line reaches for one, split it into two sentences or use a colon. Write a
  label, then a colon, then the figure. Never write a label, a dash, then a figure.
- Write no "it's not X, it's Y" phrasing and no "X, not Y" pairs. State the claim directly.
- Every dollar figure traces to a number I pasted or to arithmetic on numbers I pasted. Show the
  arithmetic on the same line or directly under it.
- Anything you need and did not get is written as [NEEDS: <the field>]. Never fill it with a
  plausible figure.
- Never use these words: leverage, seamless, robust, elevate, unlock, delve, streamline, empower,
  game-changer, transformative.
- Dollars lead every line.

Below are two result blocks from the RISE DTC tools hub: True Profit Per Order and Contribution
Margin. Under them is my orders per month.

Step 1. Restate my store as a single per-order arithmetic line, using my pasted fields:

  contribution per order
    = AOV
    - product cost
    - outbound shipping
    - payment processing
    - (return rate x AOV)
    + (return rate x resellable share x product cost)
    - (return rate x return handling cost)

Step 2. Run that line on my pasted inputs and print every step with the dollars showing. For the
payment processing term, use the figure from my Contribution Margin block, because that is the
block Step 3 checks against. If my True Profit Per Order block carries a different processing
figure, print both, print the difference, and carry on with the Contribution Margin one.

Step 3. Check your result against the returns-adjusted contribution per unit in my pasted
Contribution Margin block. It has to match to the cent. If it does not match, stop, print both
figures, and tell me which of my pasted fields would explain the gap. Do not adjust a number to
force the match.

Step 4. Print the base as a three-row table with exactly these columns:

  | figure | what it is | which tool it came from | the arithmetic |

The three rows are contribution per order before returns, contribution per order after returns, and
true profit per order after acquisition. Name the tool on every row, because the two tools charge
processing slightly differently and the figures differ by cents. Never average them. Put any
explanation of the cent-level gap in one sentence under the table.

Then stop and wait. Do not rank anything yet.

02

The sensitivity table

Reruns that line once per move you chose, with every other field held, and prices each move in dollars per order and dollars per year.

Now build the sensitivity table. One rule governs this whole step: I supply every move, you only
multiply.

[paste your list, one move per line, each in this shape: "return rate 24% -> 21%" or
"outbound shipping $7.40 -> $6.40" or "price $84 -> $88, unit cost held"]

For each move, re-run the per-order contribution line from Prompt 1 with that one field changed and
every other field held at my pasted value. Difference it against the base. Print a table with these
columns and this header wording exactly:

  | if you moved this by | new contribution per order | $/order | $/year |

Compute $/year as the $/order swing times my orders per month times 12. Print that arithmetic once,
under the table.

Honesty rules for this table, all four binding:
- Every delta in the left column is a scenario I chose. Label it that way in one line under the
  table. A delta is never a forecast, a projection, or an expectation.
- Never say a move is achievable, typical, realistic, or within reach. You have no basis for any of
  those words and I did not give you one.
- Never name an industry benchmark, an average return rate, a category norm, or a figure from any
  store other than mine. My own arithmetic is the only comparator in this chat.
- If a move changes a second field as a matter of arithmetic, say so in the row and show both
  changes. A price move changes payment processing, because processing is a percentage of price.
  Compute the moved row's processing as my processing percentage times the new price, and add
  nothing else to it. Both sides of the comparison get built the same way, or the delta is a
  measurement of your own bookkeeping.
Paste this under it
  • Your list of moves, one per line, each written as a size you picked: "return rate 24% -> 21%" or "outbound shipping $7.40 -> $6.40".

03

The ranking, and the two levers that look big

Sorts the moves by dollars per order, sets price aside, and names the levers that look bigger than they are on your numbers.

Rank the moves from Prompt 2 by $/order, largest first.

Then do these four things:

1. Handle price separately. If a price move is the largest mover, report it and set it aside in one
   sentence, because a price change carries a demand cost that this arithmetic cannot see and I did
   not give you demand data.

2. Of the remaining operational levers, print the top two side by side with the ratio between them,
   like this: "[lever A] is worth $X per order. [lever B] is worth $Y per order. That is Z times."
   Compute Z from my two figures, show the division, and print Z to two decimal places.

3. Name the two levers that look big and are small on my numbers. For each one, print the dollar
   gap between it and the top lever, and one sentence on why an operator reaches for it first.

4. Print the full ranking as a table with exactly these columns, one row per move, largest first:

  | rank | the move | $/order | $/year | note |

The note column carries "set aside" on the price row and stays empty everywhere else. Use a table
here, no dashes and no separators inside a line.

Do not tell me any lever is easy or hard. You are ranking dollars. Sequencing is my call and I make
it in the next prompt.

Then re-read the standing rules from Prompt 1 and confirm in one line that every message in this
chat holds to them. Name any line that broke one.

The one row that differs from the calculator output, and why

The calculator run behind this page prices the lever with an other-variable cost of $2.55, which is 0.029 x $88 rounded to the cent, against a base that carried $2.44. That produces $32.45096 per order, a $2.93 swing and $50,982.00 a year.

Claude rebuilt both sides of that comparison with the raw percentage, 0.029 x $84 = $2.436 on the base side and 0.029 x $88 = $2.552 on the moved side, and printed the $0.004 difference between its price-row base and the base used by every other row. That produces $32.44896, a $2.92400 swing and $50,877.60 a year.

Both figures are arithmetic on the pasted inputs. The gap between them is $0.006 per order and $104.40 a year, and it exists because the calculator rounded processing to the cent on one side of a comparison. Claude disclosed its construction in the table row and in the note under it, which is the behaviour the prompt asks for. Neither figure is invented and neither one changes the ranking.
