# Size Curve Planner

**You paste:** per size for one style, units sold, units returned, units on hand, plus lead time in weeks, target weeks of cover, unit cost, and the share of returned goods you resell.
**You get back:** returns-adjusted demand per size, the reorder quantity per size with the arithmetic, the over-buy the raw sell-through curve would have caused in units and dollars, the sizes under your minimum order quantity, and the cash the buy needs.
**Time:** about 2 minutes per style. Run it once per style and every output has the same shape.

Part of the RISE DTC Claude pack, RISE Method, Financial Health pillar.

## What this does

Sell-through says size L is a third of your sales, so the buy sheet says L is a
third of the order. Then the L units come back at the highest rate on the
style, and you have paid for a season of stock in the one size that keeps
returning.

You paste one style's sizes. Claude subtracts the units that came back and
stayed back, converts kept demand into a weekly rate, covers the lead time and
the weeks of cover you asked for, subtracts what is already on the shelf, and
hands back a quantity per size with the arithmetic printed next to it. The raw
sell-through buy sits in the same table, so the gap between the two is a number
you can take to the supplier.

The procedure below is frozen: the resellable adjustment, the cover math, the
lead-time cushion, the bounded scenarios when the resellable share is unknown,
and the ban on seasonality multipliers. Every style in the buy comes back in
the same output shape, which is what makes them add up into one purchase
order.

This works two ways: installed as a Claude Code skill, or pasted into a Claude
chat with your size table underneath it.

## Step 1: Collect the inputs

**Per size, one row:** units sold in the window, units returned in the window,
units on hand today.

**Per style, six numbers:**

| Field | What it is | Where to find it |
|---|---|---|
| Sales window | The length of the sales window in days | Whatever window the sold and returned columns cover. 90 days is the common one |
| Lead time (weeks) | Order placed to stock received | Your supplier, the last PO's actual dates |
| Target weeks of cover | Weeks of stock you want on hand after the goods land | Your call. 8 to 16 is the usual band |
| Unit cost ($) | Landed cost of one unit | Your cost sheet |
| Resellable share (%) | Of returned units, the share that goes back on the shelf at full price | Your returns grading. If you do not measure it, say so and read Step 4 |
| Minimum order quantity per size | The smallest run the supplier will take per size | Your supplier terms. Optional |

Optional and useful: **last season's buy curve** as a percentage per size. If it
is missing, say so in the output and use the sell-through curve as the
comparator.

If the sold or returned column is missing for any size, do not fill it in. Name
the size and the missing field, leave that size unplanned, and plan the rest.

## Step 2: The resellable adjustment

A returned unit that grades back to the shelf is stock you already own, so it
lowers what you need to buy. A returned unit that grades out is gone.

```
resellable = resellable share / 100

net demand (size)  =  units sold  -  ( units returned x resellable )
```

Print this per size and print the style total. Print the raw sold column next to
it so the difference is visible on the same line.

Do the same at style level and report both curves as percentages:

```
sell-through curve (size)      = units sold (size)  / units sold (style)
returns-adjusted curve (size)  = net demand (size)  / net demand (style)
```

The gap between the two, in percentage points, per size, is the finding. Name
the size with the widest gap and say what the gap costs in units.

## Step 3: Cover math and the lead-time cushion

```
weeks in window = sales window days / 7

weekly demand (size) = net demand (size) / weeks in window

coverage horizon = lead time weeks + target weeks of cover
```

The horizon carries the lead-time cushion: goods ordered today land after the
lead time, so the buy has to feed demand for every week of the lead time and
then hold the target cover once it arrives. Never plan a horizon shorter than
lead time plus cover, and never add a safety factor the operator did not name.

```
target position (size) = weekly demand (size) x coverage horizon

reorder (size) = target position (size) - units on hand (size)
```

Round to the nearest whole unit. A negative reorder is 0, and the size is
reported as covered with the surplus units printed.

Run the same three lines on the raw sold column to produce the sell-through
buy, and print both quantities per size. The difference between the two totals
is the over-buy the returns-adjusted curve removes, in units and in dollars at
unit cost.

```
cash the buy needs = total reorder units x unit cost
```

## Step 4: When the resellable share is missing

Never pick a number for it. Compute both ends and print both:

```
Scenario A, every return goes back on the shelf:  net demand = sold - returned
Scenario B, no return goes back on the shelf:     net demand = sold
```

Run Step 3 twice and print the two reorder quantities per size as a range, plus
the two cash figures. State plainly that the real answer sits between them and
that one week of grading the returns bin closes the range. Never present the
midpoint as the answer.

## Step 5: The size whose return rate points at the fit

```
return rate (size)  = units returned (size) / units sold (size)
return rate (style) = total returned / total sold
```

**Fixed threshold: a size whose return rate sits 10 or more percentage points
above the style's own rate is a fit problem in that size.** Name it, print both
rates, and say the quantity is the smaller half of the decision on that size.
Route it: run `rise-return-note-miner` on that SKU's return notes to find which
measurement is wrong, then `rise-pdp-doctor` on the page.

If no size clears the threshold, say so in one line.

## Step 6: Sizes under the minimum order quantity

If an MOQ was given, name every size whose reorder falls under it, print the
gap, and print the cash cost of buying up to the MOQ at unit cost. The call
belongs to the operator: buy up to the minimum, or drop the size from the buy.
Print both numbers and hand the decision over.

If no MOQ was given, say so in one line and skip the block. Never assume a
minimum.

## Hard guardrails

- **Never invent a seasonality multiplier.** No autumn uplift, no holiday
  factor, no trend adjustment, no "L usually runs heavier in Q4". The pasted
  window is the only demand signal in this output. If the operator names a
  multiplier, apply it and label it as their scenario, with the unadjusted
  number printed next to it.
- **Resellable share is an input.** When it is missing, print both bounded
  scenarios per Step 4 and never pick a value inside the range.
- **Never forecast a return rate.** The per-size return rates in the output are
  the ones in the pasted rows, over the pasted window.
- **Show the arithmetic on every quantity.** Weekly demand, horizon, target
  position, on hand, reorder. The buyer signs a purchase order off this, so
  every line has to be checkable by hand.
- **Never plan a size with a missing column.** Name the size and the field and
  leave it out of the totals, with the exclusion stated.
- **No industry benchmark anywhere.** No standard apparel size curve, no
  category return rate, no typical weeks of cover. The style's own numbers are
  the only comparator.
- **No em dashes and no double hyphens, including inside tables.** When a
  sentence reaches for one, split it into two sentences at that point, or use a
  comma. "L returns at 37.8% - well above the style" becomes "L returns at
  37.8%. The style runs 25.3%."
- **No corrective-contrast phrasing.** Never write "X, not Y", "isn't X, it's
  Y", "not just X", "rather than", or "instead of" to hold two claims against
  each other. This includes the comma form. Write the claim that is true and
  stop. "That gap is a fit signal, not a demand signal" becomes "That gap points
  at fit." "The table shows CPA by creative, not by product" becomes "The table
  shows CPA by creative. Product is outside it." "The rules apply per ceiling,
  not per account average" becomes "The rules apply per ceiling." "Read the
  notes rather than the tag" becomes "Read the notes."
- **Never use:** leverage, seamless, robust, elevate, unlock, delve, streamline,
  empower, game-changer, transformative.
- Units and dollars first on every line. Plain buyer-desk tone, no hype, no
  sign-off.
Works pasted straight into claude.ai as well.

The resellable share is an input you supply. When you cannot, the skill computes both ends, prints the reorder as a range, and says the answer sits between them. No seasonality multiplier and no forecast return rate appears unless you name one, and every quantity shows its arithmetic.

Why a skill file

What the file freezes

You run this once per style, as many times as the buy has styles. Runs that all produce the same table add up into one purchase order. A format that drifts run to run means retyping every one of them.

It also carries a real procedure, and it is the part that gets retyped wrong: subtract the returns that go back on the shelf from the ones that do not, turn kept demand into a weekly rate, cover the lead time and then the weeks of cover on top of it, subtract what is already in the warehouse. Miss the lead-time half of that and you have bought short by your whole lead time on every size. The skill file holds the order of operations so the buyer holds the decision.

One more thing it holds: what to do when you do not know your resellable share. It computes both ends, every return goes back on the shelf and none of them do, prints the reorder as a range, and says the answer sits between the two. It never picks a number in the middle and never applies a seasonality multiplier you did not give it.
